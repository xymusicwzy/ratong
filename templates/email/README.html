仁爱通 · Supabase 邮件模板安装说明

本目录包含与当前网站认证流程配套的 HTML 邮件模板。请管理员在 Supabase 项目 Authentication → Email Templates 中逐项复制对应 HTML 内容。注意：GitHub 上的模板文件不会自动同步到 Supabase Auth，必须在控制台粘贴保存后才会用于实际发信。

模板对应关系

  • Confirm signup / 注册确认：signup-otp.html。邮件模板使用 {{ .Token }}，用户点普通网页按钮后在 #confirm-email 页面输入邮箱和 6 位 OTP，调用 email OTP 验证。
  • Invite user / 用户邀请：invite.html。改用 {{ .Token }}，邮件按钮指向 https://xymusicwzy.github.io/ratong/#invite；用户输入邀请邮箱和 6 位验证码，使用 verifyOtp 的 type: 'invite' 完成验证，再设置密码。
  • Reset password / 密码重置：recovery.html。使用 {{ .ConfirmationURL }}。
  • Magic link / 邮箱快捷登录：magic-link.html。使用 {{ .Token }}，并在网站输入验证码。
  • Change email / 邮箱变更：change-email.html。

必须核对的项目设置

关键：Confirm signup 和 Invite user 两个模板都要替换。只替换 GitHub 文件不会影响 Supabase 实际发出的邮件；若 Supabase 中仍保留旧的 {{ .ConfirmationURL }} 邀请模板，邮件扫描器仍可能提前访问一次性链接。

  1. 在 Authentication → URL Configuration 中将 Site URL 设置为 https://xymusicwzy.github.io/ratong/，并允许对应 Redirect URL。
  2. 在 Authentication → Providers → Email 中启用 Email OTP，并设置合适的验证码有效期和频率限制。
  3. 配置自己的 Custom SMTP 服务及发件人邮箱，并完成发件域名验证（SPF / DKIM，建议配置 DMARC）。默认内置 SMTP 不适合面向真实学生邮箱批量投递，不能据此保证外部邮箱收件。不要把 SMTP 密码、服务密钥或 service_role key 放入网站代码或聊天消息。
  4. 保存后分别测试 Confirm signup、Invite user、Reset password。请用非项目团队邮箱测试，并查看 Supabase Auth Logs 与 SMTP 服务商的投递日志。

Google Authenticator

OA 的“安全与邮件”页面已提供 TOTP 绑定、二维码扫描和动态码验证。管理员应为 OA 管理账号绑定验证器。验证码失效或遗失时，应由管理员按安全流程处理账号恢复。

注意

网站已提供 OTP 输入与验证代码，但 Supabase Dashboard 的邮件模板和 SMTP 发送服务属于项目 Auth 配置，不会通过 GitHub Pages HTML 自动变更。请在粘贴模板并配置 SMTP 后，再进行注册、邀请和密码重置的真实收件测试。
